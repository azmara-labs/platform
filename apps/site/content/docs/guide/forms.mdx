## Install

The adapters use React Hook Form 7, and Zod 4 or Effect 4, which are optional peer dependencies of `@azmr/ui`. Install only the ones you use:

```bash
pnpm add react-hook-form zod       # with Zod
pnpm add react-hook-form effect    # with Effect Schema
```

```tsx
import { Form, FormErrorSummary, FormField } from "@azmr/ui/rhf";
import { fieldsFromSchema, zodResolver } from "@azmr/ui/zod";
```

## A complete form

<Demo name="forms/signup" />

Submit it empty to see the summary take focus and list each error; each link moves to its field. Then try `northline` as the web address: the schema checks it asynchronously, as a real server lookup would.

```tsx
const schema = z.object({
  business: z.string().trim().min(2, "Enter your business name"),
  slug: z.string().regex(/^[a-z0-9-]{3,30}$/, "Use 3 to 30 letters, numbers or hyphens")
    .refine(isFree, "That web address is taken; try another"),
  email: z.email("Enter an email address like aroha@example.co.nz"),
  budget: z.number("Enter a monthly budget").min(0),
});

export function Signup() {
  const form = useForm<z.input<typeof schema>, unknown, z.output<typeof schema>>({
    resolver: zodResolver(schema),
    shouldFocusError: false,
  });

  return (
    <Form form={form} onSubmit={createAccount}>
      <FormErrorSummary />
      <FormField name="business" label="Business name" required>
        <Input autoComplete="organization" />
      </FormField>
      <FormField name="slug" label="Web address" required>
        <Input />
      </FormField>
      <FormField name="email" label="Email" required>
        <Input type="email" autoComplete="email" />
      </FormField>
      <FormField name="budget" label="Monthly budget" required rules={{ setValueAs: numberOrNull }}>
        <MoneyField min={0} />
      </FormField>
      <Button type="submit">Create account</Button>
    </Form>
  );
}
```

## `Form`

`Form` renders `<form noValidate>`, provides the form to everything inside it, and submits through `handleSubmit`. Pass what `useForm()` returned as `form`, the success handler as `onSubmit`, and optionally `onInvalid`. The browser's own validation bubbles are off, so the form's messages are the only ones people see.

## `FormField`

`FormField` is a [Field](/docs/components/field) bound to the form by `name`:

- It calls `register(name, rules)` on its one control, so the control's real `ref` is used and there is no `Controller`. This works for `Input`, `Textarea`, `PasswordInput`, `NumberField` and `MoneyField`. A control's own `onChange` and `onBlur` still run.
- It shows the field's error, marks the control invalid, and reads `required` from the prop or from a `required` rule.
- `rules` takes React Hook Form's register options. With a schema resolver you only need `setValueAs`, such as `numberOrNull` for a number field.
- Dirty and touched state come from the real input, so `formState.dirtyFields` and `touchedFields` work as usual.

For a control without an input ref, such as a toggle, a select or a date picker, set `controlled`: the field uses `useController` and passes `value`, `onValueChange` and `onBlur` to the child. Or render the control yourself:

```tsx
<FormField
  name="terms"
  label="Terms"
  rules={{ validate: (value) => value || "Accept the terms to continue" }}
  render={({ value, onChange, invalid }) => (
    <input
      type="checkbox"
      checked={value}
      aria-invalid={invalid || undefined}
      onChange={(event) => onChange(event.target.checked)}
    />
  )}
/>
```

`render` also gets `control`: the `id` and ARIA props that tie the label, description and error to the control. Spread it on the element that takes focus. That is how a control from another library, such as a Radix (shadcn) Select, gets its label and its error read out:

```tsx
<FormField
  name="customer_id"
  label="Customer"
  render={({ value, onChange, onBlur, ref, control }) => (
    <Select name="customer_id" value={value || undefined} onValueChange={onChange}>
      <SelectTrigger ref={ref} onBlur={onBlur} {...control}>
        <SelectValue placeholder="Select a customer…" />
      </SelectTrigger>
      <SelectContent>{/* items */}</SelectContent>
    </Select>
  )}
/>
```

## `FormErrorSummary`

The form's [ErrorSummary](/docs/components/form#error-summary). It reads the errors and the submit count from the form, takes focus after every failed submit and links each error to its field, listed in the order the fields appear on the page, even when an async check finishes last. Set `shouldFocusError: false` in `useForm` so focus lands on the summary, not on the first field.

## `FormFieldArray`

Repeating rows of fields, such as invoice lines, run through `useFieldArray`: add, remove and reorder by drag or keyboard, with focus and announcements handled. Put a `FormField` in each row with `row.name()`. See [Field array](/docs/components/field-array) for the props and an invoice demo with GST.

## `zodResolver`

`zodResolver(schema)` validates the form with a Zod 4 schema; you don't need `@hookform/resolvers`.

- It runs `safeParseAsync`, so async refinements work.
- On success, `onSubmit` gets the parsed output: trimmed strings, defaults and transforms applied. Type the form with `useForm<z.input<typeof schema>, unknown, z.output<typeof schema>>`.
- Each issue lands on its field path, nested objects and arrays included (`address.city`, `lines.1.amount`). An issue on the whole object, from an object-level `refine`, goes to `errors.root`, which the summary shows without a link.
- With `criteriaMode: "all"`, every message per field is kept in `types`.

## `fieldsFromSchema`

`fieldsFromSchema(schema)` describes each field of a `z.object`: its name, a label, the kind of control it needs, whether it is required, and its limits. It is the start of the generated forms that come later.

```ts
fieldsFromSchema(
  z.object({
    fullName: z.string().min(2).describe("Full name"),
    creditLimit: z.number().min(0).meta({ fieldType: "money" }),
    tier: z.enum(["bronze", "silver", "gold"]),
    notes: z.string().optional(),
  }),
);
// [
//   { name: "fullName", label: "Full name", type: "text", required: true, min: 2 },
//   { name: "creditLimit", label: "Credit limit", type: "money", required: true, min: 0 },
//   { name: "tier", label: "Tier", type: "enum", required: true, options: ["bronze", "silver", "gold"] },
//   { name: "notes", label: "Notes", type: "text", required: false },
// ]
```

Labels come from `.describe()`, `.meta({ label })`, or the key in sentence case. Types are `text`, `email`, `url`, `number`, `money` (from `.meta({ fieldType: "money" })`), `date`, `boolean`, `enum` or `custom`. Optional, nullable and defaulted fields are not required. Other `.meta()` keys are passed through as `meta`.

`@azmr/ui/zod` has no React in it, so a schema module that uses it can be shared with server code.

## With Effect Schema

`@azmr/ui/effect` is the same pair of helpers for [Effect Schema](https://effect.website): `effectSchemaResolver` and `fieldsFromSchema`. Use it instead of `@azmr/ui/zod` when your schemas are Effect schemas. `effect` 4.1 or later is an optional peer dependency; Effect 3 is not supported, because its Schema API is different.

```tsx
import { Schema } from "effect";
import { effectSchemaResolver, fieldsFromSchema } from "@azmr/ui/effect";

const min1 = (message: string) =>
  Schema.String.pipe(Schema.check(Schema.isMinLength(1, { message })));

const Customer = Schema.Struct({
  name: min1("Enter a name"),
  invoiceEmail: Schema.optional(
    Schema.String.pipe(
      Schema.check(Schema.isPattern(/^[^@\s]+@[^@\s]+$/, { message: "Enter an email address" })),
    ),
  ),
});

const form = useForm({ resolver: effectSchemaResolver(Customer) });
```

Submit it empty to see the summary, then try `northline` as the web address to see the effectful check run.

`effectSchemaResolver(schema)` behaves like `zodResolver`: every issue is reported, not just the first, on its field path (nested objects and arrays included); an issue on the whole value goes to `errors.root`; with `criteriaMode: "all"` every message is kept in `types`; on success `onSubmit` gets the decoded value, so transforms have run.

- **Messages come from the schema.** Put a `message` on the check that fails, as above. Without one you get Effect's own English text, such as "Expected a value with a length of at least 1". There is no message catalogue for either adapter yet.
- **Effectful checks are awaited**, so a uniqueness test against a server works. Write it with `SchemaGetter.checkEffect`.
- **A struct-level check names its field** by returning `{ path: ["confirm"], issue: "Confirm must match" }`; a plain string goes to `root`.
- **A struct-level check runs only after every field has passed.** Zod runs its object-level `refine` alongside the field checks, so a user with a bad email and a mismatched confirmation sees both errors at once. With Effect they see the email error first and the mismatch on the next submit. The adapter cannot change that: it is how Effect orders checks.
- **`type` is always `"validate"`.** Effect issues carry no error code the way Zod's do (`too_small`). The error summary uses messages, so this only matters if you read `error.type`.
- **An unexpected exception is not a validation error.** If a check throws, the resolver rejects with that same error, so you see the real bug, rather than showing its stack trace as a message on a field.

### Numbers typed into a text input

Take care with `Schema.NumberFromString` on a text input: on its own it decodes a blank (`""`) or a space as `0`, and `"abc"` as `NaN`, **without an error**. A cleared field would quietly become 0. Require text first and a finite number after:

```ts
const Quantity = Schema.NonEmptyString.pipe(
  Schema.decodeTo(Schema.NumberFromString.pipe(Schema.check(Schema.isFinite()))),
);
```

A plain `Schema.Number` does reject `""`; use it with `rules={{ setValueAs: numberOrNull }}` on the field, as in the Zod example above.

### `fieldsFromSchema` for Effect

`fieldsFromSchema(Schema.Struct({ ... }))` returns the same `FieldDef`s as the Zod version: a label, the kind of control, whether it is required, and its limits.

```ts
fieldsFromSchema(
  Schema.Struct({
    fullName: Schema.NonEmptyString.annotate({ title: "Full name" }),
    creditLimit: Schema.Number.pipe(Schema.check(Schema.isGreaterThanOrEqualTo(0))).annotate({
      fieldType: "money",
    }),
    tier: Schema.Literals(["bronze", "silver", "gold"]),
    notes: Schema.optional(Schema.String),
  }),
);
// [
//   { name: "fullName", label: "Full name", type: "text", required: true, min: 1 },
//   { name: "creditLimit", label: "Credit limit", type: "money", required: true, min: 0 },
//   { name: "tier", label: "Tier", type: "enum", required: true, options: ["bronze", "silver", "gold"] },
//   { name: "notes", label: "Notes", type: "text", required: false },
// ]
```

- The label is the `title` annotation, otherwise the key in sentence case. A `fieldType` annotation sets the type (`"money"`, say), and an annotation called `meta` is copied to `meta`.
- Limits are read from `isMinLength`, `isMaxLength`, `isGreaterThanOrEqualTo`, `isLessThanOrEqualTo` and `isBetween`. An exclusive bound (`isGreaterThan`) sets no limit, because calling it a minimum would be wrong.
- Optional, nullable and `optionalKey` fields are not required. A transform is described by its decoded type, so `Schema.NumberFromString` is a `number`.
- `Schema.Date` and `Schema.DateTimeUtc` are `date`. Other custom types are reported as `custom`; add a `fieldType` annotation to describe one.

`@azmr/ui/effect` has no React in it, so a schema module that uses it can be shared with server code.

## Accessibility

- Every field is labelled, described and wired by `Field`; errors are announced politely and linked with `aria-errormessage`.
- After a failed submit the summary takes focus and lists every problem as a link, in page order (WCAG 3.3.1 and 3.3.3).
- Keep each rule's message specific and actionable: say what to enter, not only what is wrong.
