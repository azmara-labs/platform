# AppShell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `AppShell` (top bar, sidebar, content area) in `@azmr/ui` where the desktop sidebar behaves like Jira's: it can be hidden, peeks open as an overlay when the pointer rests on the left edge, and stays open for good once the toggle button is clicked. Below a breakpoint the same sidebar is a modal drawer.

**Architecture:** Layout is CSS driven by `data-sidebar` attributes, so the server-rendered first paint is right with no script. Three small units carry the behaviour: a pure, server-safe state module (cookie), a hover-intent hook (the peek), and a context (`useAppShell`). The mobile drawer reuses the existing `Drawer` from `@azmr/ui/modal`; the nav content is the `Sidebar` element rendered once into whichever container is active.

**Tech Stack:** React 19, Base UI through `src/primitives/*`, Tailwind v4 classes from the package tokens, vitest (jsdom) with `src/test-utils`, tsup (`build/entries.json`), size-limit, Fumadocs MDX in `apps/site`.

**Spec:** GitHub issue azmara-labs/platform#292 (API), `docs/superpowers/specs/2026-11-14-layout-navigation-design.md` sections 5, 11, 14 and 15 (slice 2, PAZM-67), and the interaction design agreed in conversation on 2026-11-20 (see "Design decisions" below). Where the issue and the spec differ, the Decisions section says which this plan follows.

## Design decisions (from the owner, 2026-11-20)

- **Look:** a clean flat sheet like Toolpad's drawer: `--sidebar` surface, a `--sidebar-border` divider, quiet rounded nav items, the current page on `--sidebar-accent`. No heavy chrome.
- **Desktop modes:** the remembered choice is `pinned` (open, takes layout space, content sits beside it) or `hidden` (takes none). A hidden sidebar *peeks*: resting the mouse on a thin left-edge zone slides it over the content as an overlay; moving away closes it. Clicking the toggle button in the top bar pins or unpins. The choice is remembered in a cookie and rendered by the server.
- **Narrow screens:** no hover. The toggle opens the modal drawer.

## Open decisions to confirm before building

Each has a default the plan uses. Changing one later is cheap, so these do not block review.

1. **Entry name `@azmr/ui/shell`** (the spec) rather than `@azmr/ui/app-shell` (the issue), so later slices (launcher, account menu) share one entry.
2. **Hover-peek replaces the spec's "collapse to an icon rail with tooltips"** (spec section 5). A hidden sidebar is fully hidden. Task 6 updates the spec text. There is no rail.
3. **`useAppShell()` has a different shape from the issue** (`mode`, `setMode`, `peeking`, `drawerOpen`, `setDrawerOpen`, `isDesktop`) because "collapsed" no longer describes the states. The issue's `collapsible` prop becomes `defaultMode`.
4. **Compound names are kept** (`AppShell.TopBar`, `.Sidebar`, `.NavGroup`, `.NavItem`, `.SidebarFooter`) as statics, alongside named exports.
5. **Left out:** `PageHeader` and `Breadcrumbs` (the issue says separate), the Ctrl+B shortcut, the navigation manifest (slice 1), the launcher, account menu and the three layouts (later slices).

## Global Constraints

- Package manager pnpm; run package scripts with `pnpm -F @azmr/ui <script>`. New code goes in `packages/ui/src/components/shell/`.
- Colours come only from `--sidebar`, `--sidebar-foreground`, `--sidebar-accent`, `--sidebar-accent-foreground`, `--sidebar-border`, `--sidebar-ring`, `--background` and `--border`. No hard-coded colours, no `dangerouslySetInnerHTML`.
- Motion uses `--motion-duration-*` and `ease-standard`, so `prefers-reduced-motion` collapses it. Z-order uses `--z-sticky` (top bar), `--z-overlay` (peek) and `--z-modal` (drawer, already set by `Drawer`).
- Tailwind classes are written out in full (no string building) so the scanner finds them in `dist`, as `drawer.tsx` does.
- The cookie is `azmr-sidebar`, written with `serializeCookie` and read with `readCookie` from `src/theme/preferences.ts`, with the same options the theme cookies use.
- Interactive targets are at least 24 px. Every icon-only control has an accessible name. The sidebar `nav` takes a required label. A skip link is the first focusable element.
- Server-safe code (state module) has no React and no `"use client"`; `scripts/verify-dist.mjs` enforces this after the build.
- Commits are conventional (`feat:`, `test:`, `docs:`), imperative, first line under 72 characters, with **no AI attribution lines**. A changeset (minor, `@azmr/ui`) is required.
- Docs spelling is New Zealand English.

## Review Focus

1. **Hidden sidebar and the keyboard.** Hover cannot be the only way in. With the sidebar hidden, the toggle button is a normal tab stop, Enter pins it, and a hidden sidebar's links are not tabbable (`inert`). Pinned to hidden returns focus to the toggle. (Task 4)
2. **Touch and pen.** A tap fires pointer-enter events on touch devices; those must not peek the sidebar. Only `pointerType === "mouse"` counts. (Task 2)
3. **A menu opened from inside the peek.** Moving the pointer from the sidebar into a popover that is portalled out of it (an account menu in the footer) is a pointer-leave. The peek must stay open while anything inside it is expanded. (Task 2, wired in Task 4)
4. **Resizing across the breakpoint with the drawer open.** The drawer closes, focus returns to the toggle, and the pinned or hidden choice is untouched. (Task 5)
5. **A bad or missing cookie.** Garbage, an unknown value, or no cookie among several gives `pinned`, never a throw or an unrendered sidebar. (Task 1)
